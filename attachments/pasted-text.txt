PART 14 — SECURE ANONYMOUS APPLICATION ARCHITECTURE

Candidates do not have Supabase Auth accounts.

Therefore, anonymous application submission must be handled through a trusted backend function.

Implement a secure submission flow.

The backend must:

1. Receive the application.
2. Validate the published job.
3. Validate the employer and job relationship.
4. Validate application form fields.
5. Validate uploaded file references.
6. Verify permitted file types and size.
7. Apply rate limits.
8. Apply bot protection where configured.
9. Detect duplicate applications for the same job.
10. Create the application using server-controlled ownership.
11. Store answers.
12. Record appropriate consent.
13. Return a safe confirmation.

Never trust a client-provided employer ID or ownership ID.

Never expose the Supabase service-role key in browser code.

Temporary upload flow

For anonymous CV uploads:

- Use a secure Edge Function.
- Issue a one-time or short-lived upload authorization.
- Use an unpredictable upload identifier.
- Restrict the file to the intended application flow.
- Validate file extension, actual content and magic bytes.
- Enforce size limits.
- Prevent arbitrary storage paths.
- Verify uploaded file references before accepting the application.
- Keep uploaded CVs private.

Do not expose public CV URLs.

Duplicate application detection

Support per-job duplicate detection using normalised email or mobile information.

Avoid exposing whether a particular person has applied to an employer through public error messages.

Use privacy-conscious handling.

Candidate withdrawal

Design for an account-free withdrawal process.

Use a secure, unguessable, time-limited or revocable application-management token.

Do not expose applications through predictable IDs.

Candidate withdrawal should be implemented in the initial release if it can be completed securely without delaying the core application flow; otherwise include it in the next release.
